## 升级 Claude Max 到底能多拿到什么

先说结论的一句话：Max 是用量升级，不是功能升级。

模型、功能、Claude Code、网页和桌面与手机应用，全都和 Pro 一样。真正变化的是三件事：

- **用量上限**：Max 5x 是 Pro 单次会话用量的 5 倍，Max 20x 是 20 倍。

## Max 5x 还是 Max 20x：算一笔账

按「价格涨幅 ÷ 用量涨幅」算，两档并不等价：

- Pro 升 Max 5x：用量 ×5，价格也 ×5（$20 → $100），单位用量成本不变。
- Max 5x 升 Max 20x：用量 ×4，价格只 ×2（$100 → $200），单位成本直接砍半。

所以单看每单位用量的花销，Max 20x 是 Claude 全线方案里最便宜的用量。前提是你真的用得满。用不满，它就是最贵的闲置额度。

至于「一单位用量」具体能换多少条消息，官方只给倍数，不给死数字。一份第三方指南的估算是：每个 5 小时周期里，Pro 大约 45 条 Opus 级消息或 225 条 Sonnet 级消息，Max 5x 约 225 / 1,125 条，Max 20x 约 900 / 4,500 条。仅供参考，实际可用量受模型选择和会话长度影响很大。

## 什么人值得升 Max：三种典型画像

**画像一：每天写代码好几个小时。** 一天八小时 Claude Code，尤其还挂着多个 agent 并行跑，Pro 的 5 小时会话上限会早早击穿，周上限也会接连触顶。这类用量的地板是 Max 5x；习惯同时跑多个 agent、或者 coding 之外还堆着重度对话设计工作的人，多半得上 20x。原因很直接：agentic coding 会把整个代码库当作输入读进去，一个跨文件、跑测试的任务，几分钟烧掉的用量抵得上普通聊天一小时。

**画像二：每周写三篇长文。** 哪怕带调研和改稿，这个强度基本碰不到 Pro 的上限。这种情况下升 Max，买到的主要是安全感。

**画像三：研究型重度使用。** 看量。偶尔做几次深度研究，Pro 撑得住；每天读析几十份长 PDF，或者长研究任务一个接一个地跑，Pro 的会话上限就会被打穿，这时 Max 5x 开始值回票价。非写代码的场景里，Max 20x 几乎没有成立的理由，除非你是在用一个账号跑内容工厂。

判断信号说穿了就一条：不是「你觉得自己用得多不多」，而是「你有没有频繁停下来等限额重置」。一周平均等待超过一次，升；从没碰到过，留 在 Pro。想好了的话，[👉 点这里选档位订阅](https://bewild.ai/?code=ACCPAY)，之后用量变了随时可以再调。

## 用量限制规则：决定之前先看懂这一节

Max 的额度大，但限制机制得先弄明白，免得升完才发现和想的不是一回事：

- **5 小时会话上限**：每 5 小时重置一次，Pro 和 Max 都有。
- **周上限**：跨所有模型计算；重置时间是绑定账户的固定时刻，和你什么时候订阅、什么时候开始用无关，每个周期发放完整周额度。
- **Fable 的单独周上限**：Max 方案针对 Fable 还有一条独立的周上限。
- **所有端共享一个池子**：网页、桌面、手机应用里聊天，终端里跑 Claude Code，或者在 VS Code、Cursor、JetBrains 系 IDE 里用，全部活动算同一份额度。

> 最容易踩的坑就在这：升了 Max 不等于 Claude Code「不计费」。并行 agent 和长任务烧额度的速度非常快，Settings 里的用量页要常看。

接近上限时会有提醒，触顶之后有三条路：等重置；选择用 usage credits 继续用（这部分单独计费）；或者用限额重置（如果账户有的话）直接把 5 小时或周上限补满。另外官方保留视情况追加周/月上限和功能级限制的余地，用来保障整体公平访问——Max 用户也可能被调，只是概率低得多。

4. 选 5x 或 20x

几个特殊情况：

- **Max 档位之间升级**（5x → 20x）：同样立即生效、按比例补差；已领取的 API 额度会先按比例补发，下个周期起按新档位发。
- **年付 Pro 转 Max**：如果年付方案的剩余价值大于 Max 价格，差额会以账户余额形式退回，抵扣以后的订阅费。注意账单地址必须和原订阅一致，地址变过就得先取消 Pro、等订阅到期再重新订。
- **通过 Google Play 订阅的**：升级时按新方案全价扣费，旧方案未用完的价值折算成天数加到新周期里。
- **降级**（20x → 5x，或 Max → Pro）：一般在下个计费周期开始时生效，当前权益保留到已付费期结束。
- **续费**：默认每个计费周期结束自动续订，随时可以取消。
